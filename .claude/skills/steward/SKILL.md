# 凪の島 — NAGI（一人称3D探索） のPR監督

正本は `CLAUDE.md` → `AGENTS.md` / `docs/DEVELOPMENT.md`。このスキルはそれを実行する手順で、矛盾したら正本が勝つ。
標準の安定化ルール。medium以上は別担当の独立レビュー、highは事前の技術設計が必要。

## 権限の境界（どのPRでも同じ）

- mainへ直接push・force-push・rebaseによる履歴の書換え・PRの承認(Approve)をしない。マージは自動操縦期の規程どおり（必須チェック `rules`・`browser`・`gate` と GitHub の auto-merge）。採用済みで合格したPRに auto-merge を仕掛けるのはよい。
- GitHubのSettings・Ruleset・Secrets・Variables・Pages設定・リポジトリ名・表示名・保存キーを変えない（main が壊れたときに `AUTOPILOT` を off にする非常停止係だけが例外）。`.github/workflows` は、はねさんが配線の修正を頼んだときだけ変える。
- 他の人やAIのブランチを直すときは、最新mainを **merge commit** で取り込む（rebase・amendしない）。
- 承認されていない仕様（新しいマップ・数値・演出・物語・ルール・課金・保存）を、PRの「ついで」で足さない。必要なら提案Issueを書いて人間に返す。
- トークン・個人のチャット・ローカルのスクリーンショットや `test-results/` をコミットしない。

## 1本のPRを監督する手順

1. **現在地**：`git fetch origin`、PRのhead SHA・base・対応Issue・作成者（Codex/GPT/人間/Claude）を確認。Issueが無い・採用根拠が書かれていないPRは、コメントで「採用根拠の確認待ち」と人間に返し、仕様の中身を推測で補わない。
2. **競合**：mainと競合していれば、PR headへmainをmergeして解消し、関係するテストを再実行してからpush。両側が同じロジックを変えて片方の振る舞いを失う場合は、直さず人間へ質問。
3. **CI**：`rules` / `browser`（このrepoのジョブ名は下）を確認。赤ければ原因をこのPRの差分の中で特定して直す。「たまたま失敗」は原因にしない。再実行は1回まで。テストのスキップ・削除・弱体化で緑にしない。
4. **差分の監査**：下の「リスクの見分け方」で low/medium/high を決め、AGENTS.mdの不変条件を1つずつ照合する。PR本文は作成者の主張であって検証済みの事実ではないので、コード・テスト・Git履歴で確かめる。独立かどうかは**セッション単位**で判断する。Codex/GPT/人間が書いたPR、またはコミットやコメントにある `Claude-Session:` のURLが今のセッションと違い、このセッションが実装に関わっていないPRなら、このレビューを**独立監査**として記録できる。今のセッションで書いたコミットを含むPRでは「自己確認」と書き、独立監査と呼ばない。
5. **直してよい範囲**：CI失敗・明白なバグ・テスト追加・誤字・PRの目的の範囲内の小修正は、そのPRのブランチ（このリポジトリ内のブランチに限る。forkには触らない）へpushしてよい（2026-10-20、はねさんが「朝までに反映・実装」を希望し、方針をClaudeに委任）。
   - pushの前に、下の「このrepoの検査」を全部実行して成功を確かめる。CIの修正なら、先に元の失敗を再現する。
   - 1つのPRにつき、1回の巡回でpushするのは検証済みの1回まで。そのpushでもCIが赤いままなら、それ以上は触らず、原因と修正案をコメントに書いて人間へ返す。
   - 設計を変える提案（ファイル横断のリファクタリング、仕様・数値・API・保存形式の変更）や、危険度highの箇所の書き換えは、pushせずコメントで提案し、人間かPR作成者の判断を待つ。
6. **記録**：PRへ1件のコメントで、次の形で残す（PASS/WARN/BLOCKは報告語で、CIや人間承認の代わりにならない）。

```
## Claude監督レビュー
- 判定：PASS / WARN / BLOCK（リスク：low/medium/high、独立監査 or 自己確認）
- 対象SHA：<sha>
- 実行したテスト：<コマンドと結果>
- 不変条件の照合：<破れていない/破れている項目>
- 直したこと：<push したコミット、なければ「なし」>
- 未検証：iPhone実機・WebKit・実耳 など
- 人間に決めてほしいこと：<なければ「なし」>
- 試遊項目：<iPhoneで見る操作>

---
_Generated by [Claude Code](https://claude.ai/code)_
```
最後の3行（空行・`---`・署名）は、GitHubに書くコメントには必ず付ける。

7. **引継ぎ**：PRが人間の判断待ちになったら、それ以上の変更はしない。同じhead SHAに「Claude監督レビュー」が既にあり、それ以降にmain・CI・レビューが変わっていなければ、新しいコメントを書かない（二重投稿をしない）。

## 自動操縦期の監督（2026-11-14〜）

毎日15時の昼ランは廃止した。マージは必須チェック（`rules`・`browser`・`gate`）と GitHub の auto-merge が行う（仕組みは `docs/AUTOPILOT.md`）。この節は、はねさんに「監督して」「見回って」と頼まれたときと、明け方の巡回で使う。

0. **準備**：`git fetch origin`、`npm run check` で基準を確かめる。変数 `AUTOPILOT` の状態と「自動操縦の日報」Issue の最新コメントを読む。
1. **棚卸し**：「main is red」Issue、`stuck`・`needs-info`・`lane/claude` のIssue、開いているPRを一覧にする。
2. **事後監査**：前回の監督以降にマージされたPRを古い順に見る。差分を `AGENTS.md` の不変条件と1つずつ照合し、上の「記録」の形でPRへ1件コメントする（マージ済みでも書く）。BLOCK相当なら、修正のIssueを立てるか、`revert` ラベルを付けた revert PR を出す（自動でマージされる）。
3. **stuckの救出**：`stuck` の原因をログとPRで特定する。PRの目的の範囲で直せるものは直して push し、`stuck` を外す。仕様の判断が要るものは「決めてほしいこと」にまとめる。
4. **方向の調整**：同じ場所を別方向に変えるIssue・PRや、`docs/DIRECTION.md`・不変条件と矛盾する案を見つけたら、はねさんの最新の発言（新しい日時のIssue）を優先して1つの筋に揃える。判断がつかない矛盾は両方を実装せず、日報のIssueに「決めてほしいこと」として書く。
5. **記録**：「自動操縦の日報」Issue に1件コメントする：監査したPRと判定、直したこと、revert、未検証（iPhone実機・聴感・独立監査）、夕方に試してほしい点、はねさんに決めてほしいこと。

独立監査について：GPT・Codex・自動操縦の実装係・人間が作ったPRを別のセッションで見るのは独立監査。自分のセッションで書いた差分は自己確認なので、「独立監査は未実施」と記録する。

## 明け方の巡回（スケジュール実行で使うとき）

1. 上の「自動操縦期の監督」の0〜5を行う。
2. 時間が残れば、開いているPRを古い順に見て、上の「1本のPRを監督する手順」の1〜7を行う（マージ自体は auto-merge に任せる）。
3. 朝の報告は、PRごとに「判定・対象SHA・直したこと・人間に決めてほしいこと・試遊項目」を1行ずつ。成功していないものを成功と書かない。GitHubに接続できないなど途中で止まったら、どの段階で何が失敗したかを書いて終える。
4. 巡回では、定期タスクの作成・変更、他のリポジトリの操作、関係のないコネクタの操作をしない。

## このrepoの検査

CIのジョブ：`Nagi checks` の `rules` / `browser`

```sh
npm run build && npm run check
git diff --exit-code -- dist/ .nojekyll   # 生成物をコミットし忘れていないか（CIと同じ）
# ブラウザ（クラウドではSessionStartフックが /tmp/nagi-qa と CHROMIUM_PATH を用意）
/tmp/nagi-qa/bin/python tests/browser-check.py
/tmp/nagi-qa/bin/python tests/controls-check.py
/tmp/nagi-qa/bin/python tests/world-check.py
/tmp/nagi-qa/bin/python tests/sky-check.py

```
ソースを変えたら `npm run build` の生成物（`dist/nagi-standalone.html` など）も同じコミットに含める。生成物を手で直さない。

## リスクの見分け方

| リスク | このrepoでの例 |
|---|---|
| low | docs、文言、字幕の誤字 |
| medium | `dist/island.js` の景物・島民・音、`dist/index.html` / `dist/style.css` の開始画面やUI、単一の地域追加 |
| high | `dist/movement.js`（入力・加速・衝突）、`dist/terrain.js`（地形・高さキャッシュ）、入力の解除・復帰、将来の保存・世界状態 |

## 監査で必ず照合する不変条件（要約。詳細はAGENTS.md）

- 片指の起点は中立、縦スライド前後・横は旋回。解除・キャンセル・二本指・blur・回転・背景化で入力を必ず消す。
- 視点固定・FOV68°・頭の揺れなし。速度 14.4 / 16.2 / 7.2 / Shift 18 を承認なしに変えない。
- 描画・移動・カメラは同じ三角形地形の高さ。高速でも薄い物・海へ抜けない。
- 足音は実移動距離と地面で鳴る。戦闘・クエスト・セーブなし。root→distの入口・manifest・アイコンを保つ。
